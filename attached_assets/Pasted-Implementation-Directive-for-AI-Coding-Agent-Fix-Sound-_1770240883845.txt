Implementation Directive for AI Coding Agent: Fix Sound Control UI
Objective
Fix multiple broken audio control issues: overlapping UI, non-functional volume slider, unreliable mute behavior, and audio state desync. Users cannot properly control audio playback.
Step 1: Locate Audio Control Components
Task: Find all audio-related UI and logic.
What to find:

Sound/volume bar component in the UI
Audio player element (HTML5 <audio> tag or custom player)
Volume slider component
Mute/unmute button
Search bar component (being overlapped)
Audio state management (React state, Redux, context)
Volume control event handlers
CSS for audio controls positioning

Task: Stop sound bar from overlapping search bar.
What to fix:

Inspect CSS z-index values for sound bar and search bar
Ensure search bar has higher z-index than sound bar (or vice versa based on design)
Check if components have position: absolute/fixed causing overlap
Verify proper layout structure (flexbox, grid) to prevent overlaps
Add proper margins/padding between components
Test on different screen sizes (mobile, tablet, desktop)
Ensure controls stack properly when viewport is narrow


Step 3: Fix Volume Slider Drag Behavior
Task: Make volume slider draggable on desktop.
What to fix:

Find volume slider input element (likely <input type="range">)
Check if mouse events are being captured: onMouseDown, onMouseMove, onMouseUp
Verify slider isn't blocked by overlapping elements (use browser DevTools to check hit area)
Ensure CSS doesn't have pointer-events: none on slider or parent
Check if slider is disabled or has wrong event handlers
Test both click (jumping to position) and drag (sliding smoothly)
Add touch events for mobile: onTouchStart, onTouchMove, onTouchEnd
Verify slider value updates both visually and in state during drag


Step 4: Sync UI State with Audio Element
Task: Ensure UI controls reflect actual audio state at all times.
What to implement:
Two-way binding:

UI controls should read from actual audio element properties, not separate state
When user interacts with UI, update audio element AND state
When audio element changes (programmatically or via browser controls), update UI

State sources of truth:

Volume: Read from audioElement.volume (0.0 to 1.0)
Muted: Read from audioElement.muted (boolean)
Playing: Read from !audioElement.paused

Add event listeners to audio element:

volumechange event → update volume slider UI
play event → update play button UI
pause event → update play button UI
Listen to these events and update React state accordingly

Remove duplicate state:

Don't store volume in both React state AND audio element
Use audio element as single source of truth
React state should only mirror audio element for rendering


Step 5: Fix Mute/Unmute Logic
Task: Make mute button work reliably.
What to fix:
Mute button behavior:

Clicking mute should set audioElement.muted = true
Clicking unmute should set audioElement.muted = false
UI icon should reflect current muted state (speaker vs muted icon)
Don't rely on separate boolean state - read directly from audioElement.muted

Common bugs to fix:

Check if mute is toggling volume to 0 instead of using muted property (wrong approach)
Verify mute state persists (doesn't randomly reset)
Ensure unmuting restores previous volume level
Check if multiple event handlers are firing (causing random behavior)

Mute implementation:
When user clicks mute:
1. Set audioElement.muted = true
2. Update UI icon to muted icon
3. Keep volume slider at current position (don't reset to 0)

When user clicks unmute:
1. Set audioElement.muted = false
2. Update UI icon to speaker icon
3. Audio resumes at previous volume level

Step 6: Fix Audio Playback Reliability
Task: Ensure audio plays/stops consistently.
What to fix:
When audio doesn't play:

Check browser autoplay policy (modern browsers block autoplay)
Ensure play is called after user interaction
Check for errors: add audioElement.addEventListener('error', handler)
Verify audio source URL is valid and accessible
Check if multiple play/pause commands are conflicting
Ensure audio isn't muted when trying to play

When audio plays while muted:

Verify muted state is set BEFORE calling play()
Check if play() is being called from multiple places
Ensure muted state isn't being overwritten after setting
Check if volume is being confused with mute

Play/pause logic:
To play:
1. Check if audio is already playing (avoid double-play)
2. Call audioElement.play()
3. Handle promise (play returns promise in modern browsers)
4. Catch errors (autoplay blocked, etc.)
5. Update UI to playing state

To pause:
1. Call audioElement.pause()
2. Update UI to paused state

Step 7: Implement Proper Volume Control
Task: Make volume slider control audio volume correctly.
What to implement:
Volume slider onChange:

When slider value changes, update audioElement.volume = sliderValue / 100
Audio volume range is 0.0 to 1.0, slider is typically 0 to 100
Update immediately (real-time feedback as user drags)
Unmute automatically if user increases volume while muted
Store volume preference in localStorage

Volume persistence:

Save last volume setting to localStorage
Restore volume on page load/refresh
Default to reasonable level (e.g., 70%) if no saved preference

Volume change flow:
User drags slider:
1. Get slider value (0-100)
2. Convert to audio volume (0.0-1.0)
3. Set audioElement.volume = convertedValue
4. If muted and volume > 0, unmute automatically
5. Save to localStorage
6. Update UI slider position
