Implementation Directive: Fix Core UI and State Bugs
What This Is
Critical stability issues across the application causing unreliable behavior: non-responsive search, overlapping UI elements, broken mobile interactions, and state desynchronization. These aren't cosmetic bugs—they're systemic failures affecting billing accuracy, user trust, and revenue.
Root Causes Identified

Event handling conflicts - Multiple handlers fighting for same events
Z-index/layering chaos - Components stacking incorrectly and blocking interactions
State not resetting - Navigation leaves stale state causing cascading failures
No global state management - Components maintaining separate conflicting states


Step 1: Audit Event Handler Conflicts
Task: Find competing event listeners causing non-responsive UI.
What to do:

Search for duplicate event listeners on same elements
Check if parent elements are calling stopPropagation() blocking child events
Find event handlers not being cleaned up (memory leaks)
Look for addEventListener without matching removeEventListener
Check if click handlers conflict with touch handlers on mobile

Fix pattern:

Remove duplicate handlers
Use event delegation where possible
Clean up listeners in useEffect cleanup/componentWillUnmount
Use single handler per element, not multiple


Step 2: Fix Z-Index and Layout Layering
Task: Establish consistent z-index system to prevent UI blocking.
What to do:

Create z-index scale: base(0), content(1), dropdowns(100), modals(1000), tooltips(2000)
Assign each component type a specific z-index range
Document z-index values in CSS variables or constants
Fix audio UI overlapping buttons (lower z-index or reposition)
Ensure interactive elements are never blocked by decorative ones
Remove arbitrary z-index values (z-index: 9999)

Priority fixes:

Audio controls blocking buttons → reduce audio z-index
Modals under other elements → increase modal z-index
Dropdowns behind content → standardize dropdown z-index


Step 3: Fix Mobile Touch/Click Events
Task: Make all buttons work reliably on mobile.
What to do:

Replace onMouseDown/onMouseUp with onClick (handles both mouse and touch)
Ensure buttons have type="button" if inside forms
Check minimum touch target size: 44x44px
Remove -webkit-tap-highlight-color: transparent blocking visual feedback
Fix pointer-events: none on interactive elements
Add touch-action: manipulation to prevent zoom on double-tap

Test specifically:

"Create Account" button on mobile
All navigation buttons
Form submit buttons
Audio controls


Step 4: Implement Global State Reset on Navigation
Task: Clear stale state when navigating between routes.
What to do:

Add route change listener that resets component state
Clear form data on navigation away from forms
Reset audio/video players when leaving media pages
Clear search query when navigating away from search
Reset scroll position to top on route change
Clean up active timers/intervals on unmount

Pattern:
On route change:
1. Clean up current page state
2. Cancel pending API requests
3. Clear temporary UI state
4. Reset scroll position
5. Load fresh data for new route

Step 5: Centralize State Management
Task: Fix conflicting states by using single source of truth.
What to implement:

Use Context API or Redux for shared state (user, auth, theme, language)
Remove duplicate state stored in multiple components
Audio element is source of truth for audio state (not separate React state)
User profile from API is source of truth (not localStorage copies)
Make components read from centralized state, not maintain their own

States to centralize:

User authentication and profile
Theme (dark/light)
Language preference
Audio/media playback state
Usage/billing data


Step 6: Fix Search Functionality
Task: Make search consistently responsive.
What to fix:

Check if search input loses focus unexpectedly
Verify onChange handler fires on every keystroke
Ensure debounce isn't blocking search (if debounced, use 300ms max)
Check if search results clear properly
Fix search being blocked by overlapping elements (z-index)
Ensure search works after navigation back to search page


Step 7: Fix Layout Spacing After Navigation
Task: Ensure consistent spacing/layout across all pages.
What to fix:

Check if layout container resets dimensions on route change
Verify CSS doesn't accumulate/leak across pages
Ensure global styles don't get overridden per-page
Fix scroll container not resetting height
Check if flexbox/grid containers maintain structure
Remove inline styles added dynamically that persist

Common causes:

Scroll position not resetting
Dynamic classes not being removed
State affecting layout not clearing
CSS animations stuck in wrong state


Step 8: Add Comprehensive Error Boundaries
Task: Prevent single component failures from crashing entire app.
What to add:

Wrap main app sections in error boundaries
Catch errors and show fallback UI instead of blank screen
Log errors to monitoring service
Allow user to retry or navigate away
Don't let one broken component break entire page


Step 9: Implement State Debugging Tools
Task: Add visibility into state changes to catch future bugs.
What to add:

Redux DevTools or Context DevTools
Console log state changes in development mode
Add data-* attributes showing component state in DOM
Track event handler executions
Monitor navigation events and state resets
Log when components mount/unmount unexpectedly


Step 10: Create Testing Checklist
Task: Verify all critical flows work reliably.
Test scenarios:

Navigation Flow: Home → Dashboard → Settings → Back → Search → works without errors
Search: Type query → see results → navigate away → back to search → still works
Audio: Play → pause → change volume → mute → navigate → audio stops, UI resets
Mobile Buttons: Every button taps successfully on iOS and Android
Layout: No overlapping elements, proper spacing on all pages, all screen sizes
State Persistence: Theme, language, auth state survive refresh and navigation
Multi-tab: Changes in tab 1 sync to tab 2 (auth, theme, language)
Error Recovery: API fails → user sees error → can retry → doesn't break app


Critical Success Criteria
✅ Search never stops responding
✅ No UI elements block buttons or interactions
✅ All buttons work on mobile (iOS Safari, Chrome Android)
✅ Layout spacing consistent after any navigation sequence
✅ Audio controls work reliably without blocking other UI
✅ State resets properly on navigation (no stale data)
✅ User auth, theme, language persist correctly
✅ No event handler conflicts or memory leaks
✅ Z-index hierarchy prevents overlapping issues
✅ App feels stable and predictable

Final Notes
This is about reliability and trust. Users experiencing unpredictable behavior will:

Abandon signups
Cancel subscriptions
Leave negative reviews
Not recommend product

These bugs indicate systemic architecture issues:

No consistent state management strategy
No z-index/layering system
No cleanup on navigation
Event handlers not properly managed

Fix the root causes, not symptoms: Don't just fix one broken button—fix why buttons break. Don't just adjust one z-index—create a z-index system. Don't just reset one state—implement global state reset pattern.
Test thoroughly on real devices: Mobile bugs especially require testing on actual iOS/Android devices, not just browser DevTools mobile emulation.
